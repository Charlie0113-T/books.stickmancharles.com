---

## 这套书是什么

一套共**五册**的阶梯：难度从 ★ 到 ★★★★★，从"看懂 AI 在做什么"一路走到"跟 AI 搭档"。读者就是我们自己——两个用 AI 造真东西、但没受过正规程序员训练的人。所以全套书遵守四条铁律：

1. **读得懂优先**。每个概念先回答"它解决什么问题"，再谈定义。
2. **一切例子来自我们自己**。技术栈以 EchoForge 为准（Cloudflare + Vercel + Supabase + DO），工作方式以我们的真实习惯为准（VS Code 里的 Claude 插件 + Claude Code 网页版，终端只是要看得懂的配角）。
3. **每晚一章**，每章十分钟以内，结尾必有"关键领悟"和一个能立刻在自己项目里做的"试一试"。
4. **重叠是故意的**。各册之间约有一成内容重复出现——间隔重复是把知识钉牢的最好办法，遇到"这个讲过了"请当作复习，不是啰嗦。

术语表统一放在第一册附录 A，它是活的；之后每册只在末尾附"本册新词"，看完自己并进总表。

## 第三册《读懂语言》★★★（已完成）

目标不是"会写"，是**读懂 AI 写的每一个文件、能指出问题、能亲手小改**。规划十章：

1. 总论：AI 时代怎么"学"一门语言——读得懂、改得动、认得出问题
2. HTML：骨架语言——标签、嵌套成树、属性
3. CSS：样式语言——选择器、盒模型，以及为什么我们的项目里满屏是 Tailwind 的 class
4. JavaScript：动作语言——变量、函数、对象与数组、事件；浏览器里的 JS 和 Node.js 是同一门语言的两个住处
5. TypeScript：带"形状检查"的 JS——为什么 AI 偏爱它，怎么读类型标注
6. JSON 与配置文件家族：json / yaml / env，一眼认脸
7. Markdown 与 MDX：文档语言——我们未来的 docs 网站就靠它
8. SQL 再进一步：读懂一条真正的查询
9. 我们栈里的其他面孔：Python（树莓派上的 ForgeCard）、Aiken（链上合约）、bash 脚本——认识即可
10. 实战：挑一个真实文件，和 AI 一起逐行读通

## 第五册《跟 AI 搭档》★★★★★（本次交付 · 系列完结）

上半册**认识你的搭档**——它是怎么被造出来的，为什么会有那些脾气；下半册**立好共事的制度**——原"工程心法"大纲顺延。规划十四章：

**第一部分 · 认识你的搭档**

1. 预训练：它读过整个互联网——补全机器的本质、幻觉的出厂原因、知识截止、上下文窗口即工作记忆
2. 后训练：从补全机器到搭档——SFT（示范教学）与强化学习（打分教学），以及"你说得对"是怎么被奖励出来的
3. 一个模型的多种身材：蒸馏与 LoRA——为什么有又快又便宜的小模型，按任务选模型的账单思维
4. 外挂记忆：RAG 与 Embedding——为什么不把一切塞进上下文，检索增强怎么工作，你每天都在用它

**第二部分 · 和搭档共事的制度**

5. 规格驱动开发：先写清楚，再让 AI 动手
6. 给 AI 立法（进阶）：宪法、技能、护栏的完整体系
7. 测试：让机器检查机器
8. CI/CD 实战：GitHub Actions 流水线
9. 像攻击者一样思考：安全进阶
10. 技术选型：怎么决定用什么、自建还是购买
11. 不可逆系统工程学：链上开发的完整方法——那次"链上考古"的最终答案
12. 从项目到产品：发布、域名、数据、反馈
13. 开源与协作：许可证、贡献、社区
14. 毕业课：AI 时代的学习者——这套书教你的其实是同一件事

编辑纪律一条：**第一部分不是机器学习课。**每一章的落点必须是"解释一个我们每天见到的行为"——第一册第 12 章列过搭档的弱点清单（自信地犯错、会遗忘、倾向讨好），这一部分给出每条弱点的出厂原因。只讲脾气的来历，不讲实现。

## 使用与迭代规则

每册独立成文件（编号 00–05），未来 docs 网站按册分区、按章分页，结构已经留好。每册读完一遍后，最有价值的动作是回到自己的项目里把"试一试"全部补做。大纲不是圣旨：写到哪一册时觉得该增删章节，随时改这份总纲——它和我们的项目一样，持续迭代。
