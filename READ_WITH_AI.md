# Read with AI

The 62 numbered chapters in the five guide volumes now have a Read with AI action below the title, before any illustration. The existing VitePress/Vue theme, fonts, colors, 2px corners, search, navigation, manuscript/PDF source, and static hosting remain in use. Front pages and appendices keep their existing reading layout.

## Files and data flow

| File | Responsibility |
| --- | --- |
| `scripts/assemble.mjs` | Existing chapter splitter; adds the action and a small resource URL to generated frontmatter |
| `scripts/read-with-ai.mjs` | Exports source chapter Markdown and public metadata to content-hashed JSON assets; checks chapter overrides |
| `books/ai-metadata.json` | Optional AI overrides keyed by chapter slug |
| `docs/.vitepress/lib/read-with-ai/types.ts` | Chapter, mode, and options types |
| `docs/.vitepress/lib/read-with-ai/options.mjs` | Shared defaults and validation, usable by the existing Node assembler |
| `docs/.vitepress/lib/read-with-ai/build-packet.ts` | Pure, provider-independent reading protocol builder |
| `docs/.vitepress/lib/read-with-ai/providers.ts` | Four providers, their SVG variants, and the future Agent Skill link |
| `docs/.vitepress/lib/read-with-ai/open-with-ai.ts` | Clipboard and provider opening adapter, with an injectable environment for tests |
| `docs/.vitepress/theme/ReadWithAI.vue` | Menu, lazy loading, keyboard/focus behavior, bilingual feedback and recovery |
| `docs/.vitepress/theme/index.ts` | Registers the chapter action component |
| `docs/public/ai-providers/` | Owner-supplied, unmodified SVGs; provenance in its README |
| `tests/read-with-ai.test.ts` | Protocol, source identity, completeness, metadata and provider failure tests |
| `package.json`, `package-lock.json`, `tsconfig.json`, `eslint.config.mjs` | Development-only lint, typecheck and test tooling |
| `.gitignore` | Excludes generated JSON and VitePress temporary bundles |
| `docs/guide/*/ch*.md` | 62 regenerated pages, each with only the resource field and component insertion |

`books/*.md` → existing H1 chapter split → full source Markdown + book/chapter/title/slug/canonical URL/options → `docs/public/ai-reading/<volume>-ch<number>.<hash>.json`.

The resource hash changes when content or metadata changes. Resources are regenerated by `assemble`, `docs:dev`, and `docs:build`, and are excluded from Git. The component checks that the returned slug matches the current chapter. It aborts stale requests when navigating, times out failed loads, and supports retry.

Opening the menu lazily imports the builder and adapter and fetches only this chapter. The full source Markdown is appended without summarization or truncation. Website-only SVG illustrations and rendered HTML are not scraped. Initial client loading includes the small UI and provider configuration, not the chapter packet or teaching prompt. Total JSON for all 62 current chapters is about 171 KB; only one is requested per interaction.

The packet teaches from the reader's actual project: Need → Tool → Concept and Understand → Find → Do → Show → Verify → Next. It adapts to existing knowledge, offers small practical steps, and always requires evidence for actual computer operations. A conceptual chapter can skip a computer exercise; it cannot waive verification of an operation that was attempted.

## Chapter options

The existing `stars` and `readTime` fields are unchanged. Generated pages gain `readWithAI`, a URL to the current public chapter resource. AI overrides live alongside the manuscripts because the repository has no handwritten per-chapter frontmatter: editing generated pages would lose changes on the next assembly.

For example, edit `books/ai-metadata.json`:

```json
{
  "guide/02/ch01": {
    "mode": "setup",
    "projectFirst": true,
    "verify": true
  },
  "guide/01/ch03": {
    "mode": "concept",
    "verify": false
  }
}
```

Run `npm run assemble` afterwards (restart `docs:dev` if needed). Supported modes: `concept`, `setup`, `practice`, `debug`, `project`, `reference`. The default is `concept`, with `projectFirst: true`; `verify` defaults to false for concept and true for other modes. Invalid modes, non-boolean flags, and unknown chapter slugs fail assembly. `projectFirst: false` permits a brief orientation first, but never overrides the protocol's requirement to connect learning to a real need.

## Provider strategy

| Provider | Destination | Strategy |
| --- | --- | --- |
| ChatGPT | `https://chatgpt.com/` | Copy full packet, then open |
| Claude | `https://claude.ai/new` | Copy full packet, then open |
| Gemini | `https://gemini.google.com/app` | Copy full packet, then open |
| Grok | `https://grok.com/` | Copy full packet, then open |
| Copy for any AI | No destination | Copy full packet only |

All four deliberately use clipboard fallback. No prompt is placed in a query string and no chat is automatically submitted. This avoids depending on consumer-platform URL parameters or their size limits. This decision does not claim that all forms of prefill are impossible: for example, Anthropic documents [Claude Desktop deep links](https://support.claude.com/en/articles/14729294-opening-claude-desktop-with-a-link), but that requires the desktop app and is not a universal web handoff. Google documents [entering prompts in the Gemini web app](https://support.google.com/gemini/answer/14886647?hl=en). OpenAI's [shared links](https://help.openai.com/en/articles/7925741-chatgpt-shared-links-faq) concern existing conversations, not this full-chapter handoff. Reviewed 2026-09-12.

Copy starts during the click while the source page has focus. The adapter reserves an empty tab synchronously, clears its opener, and navigates only once copying succeeds. Denial closes the reserved tab and exposes the full packet in a selectable readonly textarea. Popup blocking preserves the copy and displays an explicit provider link. Copy for any AI opens no tab. There is no provider API, account integration, analytics service, browser data collection, or project data collection.

## UI and accessibility

The trigger and provider rows have at least 44px touch targets. Enter/Space opens or selects; Arrow Up/Down cycles; Home/End jumps; Escape closes and restores trigger focus. Tab can leave the menu, and outside pointer/focus closes it. Icons are decorative beside readable provider names. Loading, success, and failure have bilingual text and a live status region.

At widths below 768px the menu expands in document flow so it does not cover the title or chapter body. Desktop uses a bounded popover. Provider SVGs use the supplied black/white variants under the site's theme class; Gemini retains its supplied colors. There are no new fonts, colors, UI libraries or animations.

## Development and validation

Use Node 20.19+ (the existing `.nvmrc` remains on Node 20); Node 22 is also supported. The normal assembly/build/PDF commands remain plain Node. Tests use `tsx` only to execute typed test fixtures. There were no prior lint/typecheck/unit-test scripts; these checks were added without removing existing tests or changing unrelated UI code. Lint excludes generated files and documents two intentional legacy patterns (full-width typesetting space and NUL regex placeholders).

```sh
npm run lint
npm run typecheck
npm test
npm run docs:build
npm run docs:preview
```

Restart the preview server after rebuilding: VitePress's preview caches its static-file inventory, so a running preview may return 404 for newly hashed bundles.

Validated on 2026-09-12:

- Lint, Vue/TypeScript typecheck, 10 unit/integration tests, and the VitePress production build (including link checking) pass.
- Every numbered chapter matches its original manuscript block, title and canonical URL. A large synthetic bilingual packet is preserved without truncation.
- Chromium desktop at 1440px: menu rows, source SVGs, light/dark switching, real clipboard copy, all four provider destination tabs, keyboard navigation/wrapping, Escape/Tab/focus restoration.
- Chromium mobile emulation at 320px and 375px: menu bounds and at least 44px rows; real clipboard copy with visible feedback; light/dark appearance. Menu is in document flow.
- Simulated clipboard denial exposes and selects all 3,421 characters of the first chapter packet; simulated popup blocking exposes a direct provider link; simulated loading failure closes the overlay and retries successfully.
- SPA chapter navigation resets the packet; subsequent copy contains chapter 2 and its canonical URL, without chapter 1's title. Local search for Git returns chapter and reference results.
- Browser resource inspection confirms no chapter JSON or prompt builder request before opening the menu. Current browser checks report no application errors.

## Agent Skill and limits

easycode (`stickmancharles-ai-guide`) v1.0.0 is published at https://github.com/Charlie0113-T/stickmancharles-ai-guide. Remote installation was verified on 2026-09-13. The local `AGENT_SKILL` metadata in `providers.ts` now points to this repository, and the entry reads `easycode · Agent Skill`. The website still needs its normal deployment to expose this local change. Skill tool execution remains in the agent runtime, separate from ordinary chat reading; chapter sources and teaching principles are shared.

Browser clipboard support requires HTTPS or localhost and may be denied. The manual copy UI is the recovery path. Provider login and chat input/context limits remain external; the site preserves the whole packet and never silently shortens it. Current manuscript chapters are Chinese; a bilingual/English source fixture verifies language preservation without inventing English site routes. Real-device Safari/Firefox behavior and authenticated conversations require separate cross-browser testing.

Existing mobile header limitation: at a 375px viewport, the navigation/search/language row produces a 441px document width. Hiding the entire new Read with AI component leaves that width unchanged. The new menu's right edge is 351px at 375px and 296px at 320px. The unrelated header was not redesigned as part of this feature.

`npm audit` currently reports 4 findings in the existing VitePress/Vite/esbuild/nanoid dependency chain. Framework upgrades are outside this feature and were not forced into it.
