# 第 12 章 从项目到产品 · 发布

项目和产品差一个字，差的是三件事，<strong>别人能找到，别人能用起来，你能负起责来</strong>。发布就是把这三件事补齐的过程。books.stickmancharles.com 的上线是我们最新的一次发布，这一章就用它当标本。

<strong>让人找得到。</strong>门面三件套你已经会了，域名（第一册第 6 章），部署（第四册第 1 章的 CNAME），HTTPS（平台自动）。再加半件，让搜索引擎读得懂，语义化的标题层级，每页说清自己是什么的描述，一份 sitemap。不必钻研 SEO 玄学，<strong>把内容写清楚本身就是最好的 SEO</strong>。

<strong>让人用得起来。</strong>发布前做一次<strong>陌生人测试</strong>，把网址发给一个完全不了解背景的人，你只观察，不解释，记下他卡住的前三个地方，那三处就是你的下一批工单。做产品的人对自己的东西全是盲区，陌生人的第一分钟比你的一百小时值钱。

<strong>让你负得起责。</strong>上线那一刻，第四册第 9 章的三件套从练习变成义务，uptime 探针盯着门口，日志地图画好，支出提醒设上。原则依旧，<strong>比用户先知道</strong>。责任还有安静的一半，能不收集的数据就不收集。收得越少，泄露不了的越多，这是最省力的隐私保护。

<strong>发布的心态</strong>，两条都反直觉。其一，<strong>上线是起跑线</strong>，发布那天你才第一次拥有真实的反馈来源，之前全是猜。其二，<strong>小而全真，胜过大而未完</strong>。我们的站规"导航里只放写完的东西"，其实是一条通用的发布哲学，用户可以原谅功能少，很难原谅点进去是空的。诚实的边界本身就是一种质量。

最后把这套书自己的发行流程写进正史，它把前几章全串了起来。书稿冻结出 PDF，发行物，不进 CI，第 8 章。校对，放一天，再核对，不可逆前的冷静期，第 11 章。EchoUploader 链上存证，出生证明。书架上架。一本书的发布，走的是和一个产品完全相同的纪律。

::: info 关键领悟
发布拆开是三样，找得到，用得起来，负得起责。上线是起跑线，而小而全真的东西，永远好过大而空的。
:::

::: tip 试一试
给已上线的站做一次真的陌生人测试，发出去，闭嘴，记录前三个卡点。然后检查负责三件套，探针，日志地图，支出提醒，缺哪个当晚补上。
:::
