# 第 10 章 技术选型 · 怎么决定用什么

每个项目都要回答几十次同一类问题，用哪个框架，哪个库，哪家服务，自建还是购买。选错的代价要到半年后才显形。这一章给一张四问的决策卡，外加 AI 时代新增的一条。

<strong>第一问，它解决的是我现在的问题，还是想象中将来的问题？</strong>为"将来可能需要"引入的复杂度，几乎从不兑现价值，只兑现维护成本。现在的问题现在解，将来的问题将来它自己会来报到。

<strong>第二问，它够无聊吗？</strong>"无聊的技术"是行话里的褒义词，成熟，稳定，坑都被前人踩平，答案随手可查。AI 时代给这条加了一个新的、必须写进决策卡的理由，<strong>搭档最擅长的，就是训练语料里最多的</strong>。选大众技术，AI 写起来如有神助。选冷门新锐，等于亲手削弱你的搭档。同样一个功能，让 AI 用满大街的框架写和用上月发布的框架写，质量差一个档次。原因就是第 1 章的原理，补全机器补全的是它读过的世界，和偏心无关。

<strong>第三问，它的账单是什么形状？</strong>第四册第 10 章的老问题，选型时问最省钱。固定，随量，还是免费额度陷阱？超线是停还是扣？

<strong>第四问，退出成本多高？</strong>总有一天你会想换掉它。到那天，数据导得出来吗？代码绑得多深？开放格式，标准协议，能整体导出的，退出便宜。私有格式，深度绑定的，等于签了长约。选型时看一眼出口在哪，是给未来的自己留门。

自建还是购买，一条经验线切开，<strong>构成你独特价值的，自建。通用的，购买。</strong>EchoForge 的链上验证逻辑是我们的立身之本，必须自己写。登录系统全世界一个样，用 Supabase 的，第一册第 15 章早说过，别自己发明 Auth。我们自己的选型史就是这张卡的答卷。书站选 VitePress，没有自研，无聊技术加购买通用件。书架效果用纯 CSS 手写，没引入 React 组件库，这是第四问，为一个视觉效果引入整个新体系，退出成本荒谬。文字工作流用 Markdown 加 Git，第二问满分，无聊到完美。

::: info 关键领悟
四问一线，解决现在的问题吗，够无聊吗（AI 时代加权），账单什么形状，出口在哪。独特的自建，通用的购买。选型选的是未来六个月的生活质量。
:::

::: tip 试一试
用四问复盘你做过的一次技术选择。选对的，说出对在哪一问。选错的，找出当时漏问了哪一问。三行字，写进项目笔记。
:::
