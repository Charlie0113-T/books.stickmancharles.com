# 第 3 章 云端分身：Claude Code 网页版怎么用

如果说插件是坐在身边的搭档，网页版就是<strong>派驻云端的分身</strong>。心智模型三句话：你把 GitHub 仓库授权给它；它在云上的一间独立工作室（沙箱）里克隆代码、按你的任务书干活；干完把成果打包成<strong>一条分支和一个 PR</strong> 递回来（这两个词第 7 章正式讲，先记住：那是一份"请过目"的改动包）。

它和插件是分工，不是竞争。<strong>适合派给分身的活</strong>：任务大而明确、可以写成一份完整任务书的（"把所有页面的旧版按钮统一换成新组件"）；你人不在电脑前、想用手机或浏览器发起的；想同时并行推进好几件互不相干的事的。<strong>不适合的活</strong>：需要你本机环境或本机密钥才能跑的；边聊边想、方向还没定的模糊探索——那种活适合贴身搭档。

用它，你只有三个动作，每个都在考验你的基本功。<strong>派活</strong>：因为它在云上独自干活、你没法随时插话，任务书的质量几乎决定一切——背景、目标、约束、例子，一样都别省，红线更要写明。这是异步协作的第一法则：<strong>规格写多清楚，成果就有多接近</strong>。<strong>收货</strong>：去 GitHub 打开它提的 PR，在 Files changed 里逐文件审红绿差异——和第 2 章第三步一模一样，只是换了个地方。<strong>裁决</strong>：满意就合并，不满意就在 PR 里写下具体的修改意见，让它再来一轮。

::: info 关键领悟
网页版是你"提需求"能力的试金石——没有追问和补救的机会，一次说清的功力全在这里现形。
:::

::: tip 试一试
挑一个小而明确的任务派给网页版，全程只通过任务书和 PR 交流，不用插件救场。收货时给自己的任务书打个分。
:::
