# 第 6 章 GitHub 实战：建仓、上传、修改一个仓库

这一章回答一个最实际的问题：**手上有个本地项目，怎么把它变成 GitHub 上的一个仓库？**以及之后怎么持续修改它。

**第一步，云上建一个空仓。**GitHub 网页右上角 New repository：起名（小写加连字符是惯例）、选 **Public（公开，全世界可读——秘密纪律立刻拉满）还是 Private（私有，受邀才可见）**。关键一条：**不要勾选自动生成 README** 之类的初始化选项——让云上是个完全的空仓，否则它有一份历史、你本地另有一份历史，第一次推送就会打架。

**第二步，三行咒语，把本地推上去。**建完空仓，GitHub 会把这三行摆在你面前：

```bash
git remote add origin https://github.com/你的用户名/仓库名.git
git branch -M main
git push -u origin main
```

逐行翻译，咒语立刻祛魅。第一行：给云上那个仓库在本地存个"联系人"，名字叫 **origin**（惯例名，就像手机里存"家"）。第二行：把当前主分支改名为 **main**（现行惯例的主干名）。第三行：把 main 推给 origin，`-u` 的意思是"记住这对关系"——从此以后每天只需要裸敲 `git push`。首次推送会要求登录 GitHub 授权，跟着提示走即可。刷新网页，看到自己的代码出现在云上——记住这一刻的感觉。

**之后的修改**，就是第 5 章的循环：改 → add → commit → push，网页上随之更新。两个补充场景：**反方向**——云上已有仓库想搬到新电脑，`git clone 地址` 整仓复制（第一册讲过）；**网页直改**——README 里改个错别字，不必回本地，网页上点铅笔图标改完直接 commit。但注意：**网页上改过之后，本地就旧了**，回到本地先 `git pull` 把云上的新箱子拉下来。由此得出一条终生习惯：**动手之前先 pull**，让本地永远从最新状态出发。

::: info 关键领悟
`remote add`、`branch -M`、`push -u` 这三行一辈子只在建仓时用；真正天天用的，还是那四步循环加一个 pull。
:::
