# 第 7 章 终端：和电脑说话的第二种方式

图形界面是"指指点点"，<strong>终端（Terminal）</strong>是"直接下命令"。同一台电脑，两种说话方式。程序员偏爱终端，不是因为它酷，而是因为它<strong>精确、可重复、可自动化</strong>——一条命令可以原样再跑一遍，一百条命令可以写成脚本。也正因为如此，AI 也爱它：<strong>不管你是在 VS Code 的 Claude 插件里，还是在 Claude Code 网页版里派活，AI 真正动手时，走的都是终端命令</strong>——而且每一条都当着你的面敲。我们自己确实很少亲自开终端，但这恰恰是要读这一章的原因：你可以不常说这门语言，但你必须听得懂 AI 在用它说什么。

看得见，就应该看得懂。其实高频命令只有一小把：

| 命令 | 意思 | 记法 |
|---|---|---|
| `pwd` | 我现在在哪个文件夹 | print working directory |
| `ls` | 这里有什么 | list |
| `cd 路径` | 进入某个文件夹 | change directory |
| `mkdir 名字` | 新建文件夹 | make directory |
| `cp 甲 乙` | 复制 | copy |
| `mv 甲 乙` | 移动/改名 | move |
| `cat 文件` | 把文件内容打出来 | — |
| `grep 词 文件` | 在文件里搜这个词 | — |
| `rm 文件` | 删除 ⚠️ 没有回收站 | remove |

再补两个概念：<strong>路径</strong>分绝对的（从根写起，`/Users/charles/...`）和相对的（从当前位置写起，`./src/...`），`~` 代表你的家目录；竖线 `|` 叫<strong>管道</strong>，把前一条命令的输出喂给后一条，像流水线接力。

终端里真正危险的东西极少，基本都是删除类：看到 `rm -rf`（递归强制删除）出现在 AI 要执行的命令里，停下来多看一眼再放行。除此之外，终端不可怕——它只是"把菜单背下来的点菜方式"。

::: info 关键领悟
读完这本书，你应该能看懂 Claude Code 终端输出的百分之八十。剩下的百分之二十，问它就好。
:::

::: tip 试一试
打开终端，用 `pwd`、`ls`、`cd` 逛一逛自己的电脑，最后 `cd` 进我们某个项目的文件夹，`ls` 看看里面的结构。
:::
