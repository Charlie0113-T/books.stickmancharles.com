# 第 12 章 AI 编程的真相：你是导演，不是观众

Claude Code 这类工具在做什么？拆开看是一个循环：读你的代码库（这些进入它视野的信息叫<strong>上下文，Context</strong>）→ 理解你的意图 → 定计划 → 执行命令、修改文件 → 观察结果 → 再来一轮。它的超能力是知识面广、不知疲倦、能同时读几十个文件；它的弱点也真实存在：会<strong>自信地犯错</strong>，上下文有限（对话太长会"忘记"前面的约定），倾向于顺着你说"你说得对"，而且——最关键的——<strong>对你独有的约束一无所知，除非你告诉它</strong>。

这一条，我们付过真金白银的学费。有一次，一个看起来无害的重命名任务，AI 从头到尾执行得又快又漂亮。但它不知道我们有一份<strong>已经部署上链、部署后就无法修改</strong>的合约，必须和代码库保持一致。结果两边对不上，我们花了好几天做"链上考古"才把现场拼回来。这件事教会我们的<strong>不是"别用 AI"</strong>，而是：凡是已部署的、花了真钱的、不可逆的东西，<strong>红线必须由人来划</strong>——因为全世界只有你知道你的红线在哪里。后来我们把这些红线写成了给 AI 看的规矩，每次动那个项目前先让它读。这个做法，推荐给每一个用 AI 做真东西的人。

所以你的角色不是观众，是<strong>导演</strong>。导演做三件事：给剧本（把需求讲清楚，下一章）、划红线（什么绝对不能动）、看回放（验证结果，第 14 章）。至于打字，让 AI 去。

::: info 关键领悟
AI 把"动手"的成本降到了接近零，于是"想清楚"成了唯一值钱的事。
:::
