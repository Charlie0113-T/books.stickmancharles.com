# 第 10 章 云账单怎么读 · 成本也是架构的一部分

<ReadWithAI />

云的付费模式是水电煤，用多少付多少。好处是起步几乎免费，我们能用四大件做出真东西，靠的就是这份慷慨。风险在另一头，<strong>水电煤没有上限，账单也没有</strong>。行业里最经典的恐怖故事，是一段死循环代码整夜狂调付费接口，或者流量被恶意刷爆，一觉醒来账单多了几个零。所以读账单这件事，属于工程纪律的最后一块拼图，和抠门无关。

<strong>先看懂三种计费模型</strong>，正好对应四大件。<strong>固定月租</strong>，DO 的服务器，像房租，用不用都是这个数。这是自己养服务器藏得最深的优点，<strong>账单天然封顶</strong>。<strong>用量计费</strong>，Vercel 的函数调用与流量，Supabase 的存储与带宽，像水电，随用户增长。<strong>免费额度加超量</strong>，四大件全都送慷慨的 free tier，这是个人项目常年零元的原因。但每一家都要搞清两件事。额度线画在哪？<strong>过线之后是停还是扣？</strong>有的服务超额直接暂停，安全但会宕机。有的默默开始计费，不宕机但花钱。这个开关在各家的账单设置里，值得亲手确认一遍。

<strong>再养成三个习惯。</strong>其一，<strong>每月看一次账单</strong>，像体检，重点盯"和上月比有没有异动"，数字本身大小在其次。异动必有故事。流量涨了？被爬了？哪段代码在狂奔？<strong>账单是用钱写成的另一份监控日志</strong>，上一章的思路在这里完全适用，而且各平台都有支出提醒（budget alert），全部设上，让钱包也有自己的告警。其二，<strong>给会花钱的东西设限</strong>，付费 API 的 key 设配额，平台设支出上限。其三，<strong>定期清理僵尸</strong>，试验完忘了删的项目，闲置的服务器，自动续费的域名。云上最常见的浪费，是<strong>忘了它还在扣钱</strong>，倒不是用太多。

最后，把成本请进架构决策。第一册第 5 章"代码住哪"的选择题，现在补上最后一个维度。偶尔醒的活，serverless 按次计费最便宜。永远醒且一直忙的活，固定月租的服务器反而省。大流量的静态内容，让 Cloudflare 的缓存去扛，免费的 CDN 流量是它送你的最大一份礼物。从此评估任何方案时多问一句，"<strong>它的账单是什么形状的？</strong>"问出这一句，你就是在做架构了，比只写功能又高了一层。顺带一提这道题的另一个极端解，ForgeCard 那台树莓派，一次性硬件加一点电费，零月租，自己家机房的极致形态。没有最好的形状，只有合适的形状。

::: warning 出事时想起我
账单突然跳，先看用量图里<strong>哪条线</strong>异动（流量？调用次数？存储？），再对着异动的时间点去翻第 9 章的日志。成本异动，几乎永远是系统行为异动投在钱包上的影子。
:::

::: info 关键领悟
账单是用钱写成的监控。会读它，你既守住了钱包，又多了一双发现系统异常的眼睛。
:::

::: tip 试一试（安全档 · 只读加设置）
给自己开一次二十分钟的"账单会"，四大件的账单页各过一遍，回答三个问题。现在每月总成本是多少？哪一项离免费额度线最近？过线之后，各家是停还是扣？最后把每家的支出提醒全部设上。这个会，以后每月开一次。
:::

## 写在第四册末尾

引擎盖可以合上了。盘点一下你现在身上多出来的东西。一张从症状到层再到日志的排障地图，这是本册真正的毕业证。一套评估表结构、权限、接口的标尺。还有一种新的目光，看任何方案时，会顺口问出"它的账单是什么形状""它出事时症状会是什么"。四大件从供应商，变成了你叫得出脾气的同事。

只剩最后一册了。工具会了，语言通了，系统懂了。第五册回答最后一个问题，<strong>怎么把人的判断和 AI 的马力，装进同一套制度里</strong>，让我们能又快又稳地，造更大的东西。
