# 什么是 Vibe Coding——以及为什么这个站教的不止是它

**Vibe coding**（氛围编程）这个词由 Andrej Karpathy 在 2025 年初提出，说的是一种新的开发方式：完全用自然语言描述想要什么，让 AI 写全部代码，自己**基本不看代码**——跟着感觉走，出错了就把报错丢回给 AI，直到东西能跑。

先承认它真实的力量：vibe coding 把"从想法到能跑的 demo"的距离压缩到了接近零。周末做出一个小工具、一个游戏、一个原型，不需要任何编程背景——这在三年前是天方夜谭。我们自己的很多东西，最初也是这么"vibe"出来的。

但它有一条清晰的边界：**"不看代码"的代价，会在东西变得重要的那一刻找上门。**能跑和安全看起来一模一样；能跑和可维护看起来也一模一样。当你的项目开始有真实用户、真实数据、真实的钱——或者像我们一样，有一段**部署后永不能改**的链上合约——"跟着感觉走"就不够了。我们为此付过好几天"链上考古"的学费。

所以这个站的立场是：**有监督的 vibe coding**。

- 你可以不亲手写代码——那是 AI 的活；
- 但你必须**看得懂**它写了什么（第三册的全部内容）；
- 必须**验得住**它说的"完成了"（验证金字塔）；
- 必须**划得出红线**——哪些东西不可逆、必须由人确认（红线卡）。

一句话：vibe 负责速度，监督负责下限。这五册书教的，就是那个"监督"怎么长出来。
