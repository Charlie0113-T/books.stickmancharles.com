# 数据库

> 软件的记忆：表、行、列。

## 认脸
- 设计三句话：一个事实只存一份；关系交给外键强制守护；常走的路铺索引
- `references users(id)` = 数据库从记录事实升级为守护事实
- 九成"越用越慢"，最后查到一条缺索引的查询头上

## 常见坑
- 同一信息存两处：迟早对不上，改设计不改数据
- 删数据报 foreign key 错：那是守护在工作，别硬删，想清楚再动
