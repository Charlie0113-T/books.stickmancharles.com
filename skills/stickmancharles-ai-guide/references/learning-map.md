# Route from need to knowledge

Use when choosing what to teach next. This is a routing map, not a syllabus.

| Current need | Find in the real project | Introduce only as needed | Useful next evidence |
|---|---|---|---|
| “Where does this feature live?” | Entry point, route, component, caller | Source/config/runtime | Trace one interaction |
| “I’m afraid of breaking it” | Git status and relevant diff | Save, commit, recovery | A reviewed checkpoint |
| “I want to work with a friend” | Existing remote and collaboration rules | Branch, PR, review | Correct branch and reviewed change |
| “The button does nothing” | Handler, console, network request | Event, async, request/response | Reproduce and verify the click |
| “Where is this information saved?” | Storage call, schema, query | Persistence, table, relationship | A safe read of fixture data |
| “It works locally, not online” | Build/deployment logs and environment names | Build versus runtime; environment | Same behavior in target preview |
| “AI says it is done” | Diff, acceptance criteria, checks | Evidence versus assertion | Verified normal and relevant edge paths |

The book sequence provides optional depth: 01 maps the system; 02 introduces daily tools; 03 reads languages; 04 operates systems; 05 improves AI collaboration and verification. Start at the needed chapter, with prerequisites explained in place. Never require finishing an earlier volume.

Handoff with a concrete state: “Git is available here and this folder is the repository; the next useful step is reviewing the files for your first commit.” Continue only if that step is already authorized. If a human-only login is pending, retain what is verified and the exact remaining check.

A learning check can be simply pointing out what the changed output proves. Do not require a quiz or create a lesson tracker unless requested.
